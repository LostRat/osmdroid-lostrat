Terrain-RGB Hillshade Overlay

2026-09-06 · branch feat/terrain-rgb-hillshade · targets 7.0.3-lostrat-SNAPSHOT · usage guide: TERRAIN_RGB_HILLSHADE.md

1. What was added

A hillshade layer computed on the device from a Terrain-RGB MBTiles file, the raster DEM format MapLibre GL uses for raster-dem sources. Stock osmdroid has never had a DEM layer. The overlay draws over any base map, including none, and is driven by one file at a time through two calls, setFile and setEnabled.

Class (all in org.osmdroid.tileprovider.terrain)Role
HillshadeOverlayPublic entry point. Owns one archive and one tile provider; reads zoom range, bounds, tile size and encoding from the file; draws nothing outside the bounds; live setters for opacity, sun and exaggeration.
HillshadeTileProviderSingle-archive module provider. Calls the tile source to shade each tile. The place for the tile-edge padding fix.
HillshadeTileSourceBitmapTileSourceBase carrying encoding, sun, opacity and exaggeration. Decodes forcing ARGB_8888 so no elevation bits are lost, shades using the tile index for ground resolution.
HillshaderPure maths: metres per pixel at the tile's latitude, Horn 3x3 kernel, translucent ARGB output that is clear on level ground.
TerrainRgbEncodingbase / interval pair with Mapbox and Terrarium presets and a parser for base <b> interval <i> in the MBTiles description.
SampleHillshade (viewer)Loads the first *terrain*.mbtiles in the app's external files folder (Android/data/org.osmdroid/files[/osmdroid|/Download]), the osmdroid base path, or shared Downloads when readable; zooms to its bounds, on/off button and file picker.

2. Design decisions

  • Overlay level, not base map level. The overlay has its own provider and archive, so base map switches, offline mode and a disabled base TilesOverlay never touch it. It never joins the base provider's archive list.
  • One file at a time. Stock osmdroid's multi-archive list is irrelevant here; a second setFile closes the previous archive and swaps the provider. This keeps the consuming app to one toggle.
  • Encoding from metadata. Mapbox is base -10000 interval 0.1; Terrarium is base -32768 interval 1/256; files built with rio rgbify -b -10000 -i 1 are integer metres. The description string carries the pair. A wrong encoding does not crash, it produces relief ten times too flat, which is why the finalize step on the build side matters.
  • Overzoom through MapTileApproximater. Above the file's top zoom the last native level is scaled up. Hillshade tolerates this; it goes soft at street zoom.
  • Everything is live. Opacity, sun and exaggeration clear the overlay's cache and invalidate; tiles re-shade on the loader threads in a few milliseconds each, so the setters can sit behind sliders.

4. Known gaps

  • Tile seams. Each tile is shaded alone, so the kernel clamps at the edge and a one pixel seam shows on tile borders at high opacity. Fix in HillshadeTileProvider.TileLoader.loadTile: read the four edge neighbours from the archive, pad the grid by one pixel, shade, crop.
  • 512 px tiles on a 256 px map are scaled into the tile rectangle; mapping a z+1 request onto a quadrant of the z tile would reclaim the resolution.
  • No lat/lng elevation lookup on the overlay yet; HillshadeTileSource.elevationAt decodes a pixel.
  • Metadata detection relies on the description text. Explicit keys (layer, encoding, base, interval, tilesize) written by the build side would let readMetadata prefer them.
