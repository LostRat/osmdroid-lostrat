Design notes on MapsForgeTileCacheKeys (not bugs, but worth knowing)

  • The hash includes each map file's size and mtime. Every time a .map file is updated, a brand-new cache namespace is created and the old tiles stay in cache.db until osmdroid's normal expiry/trim runs. If maps are refreshed often, consider a one-off SqlTileWriter.purgeCache(oldSourceName) when the key changes.
  • Keys with the two-argument overloads depend on DisplayDensityManager being initialized before the key is built. The samples do this correctly (createInstance() then key, then applyDensityScaling()). If an app builds the key first, it silently gets scale-100.
  • Map order affects the hash (tested). The samples sort the file list first. Any caller must do the same or the key drifts between runs.

5. Cross-repo gap: tile cache keys

The test app's MapsForgeTileCacheHelper (committed 2026-07-03) works around the reader/writer mismatch by forcing a filesystem TileWriter and building a name from DisplayMetrics.density. The fork's f6a533888 fixes the mismatch inside MapsForgeTileProvider and keys on the render scale instead. Once the test app moves to 7.0.2-lostrat-SNAPSHOT (already in Maven Local, published 2026-08-01 07:51, which is after the commit), the helper can shrink to:

MapsForgeTileSource.createInstance(app);
Arrays.sort(mapFiles);
String name = MapsForgeTileCacheKeys.forMapsAndTheme(mapFiles, themeName);
MapsForgeTileSource src = MapsForgeTileSource.createFromFiles(mapFiles, theme, name);
src.applyDensityScaling();
MapsForgeTileProvider provider = new MapsForgeTileProvider(receiver, src); // SqlTileWriter + matching reader

Note the filesystem cache (TileWriter) and the SQL cache (SqlTileWriter) are separate stores. Switching the test app from one to the other will re-render tiles once.

Applied 2026-09-03 (uncommitted in the test app): app/build.gradle.kts now pins 7.0.2-lostrat-SNAPSHOT; MapsForgeTileCacheHelper was rewritten to compute the app's render scale once, pass it to the three-argument MapsForgeTileCacheKeys.forMapsAndTheme(), and use the two-argument MapsForgeTileProvider constructor; docs/mapsforge-tile-cache.md was rewritten to match. :app:compileDebugJavaWithJavac passes.
